1 / Problem

A gun's feel is held in five places, and four of them need a programmer

Today a designer cannot see one gun's full set of numbers in one place. Most of them can only change with a compiler and a restart. Nothing shows that a change to one gun left the others alone.

Text file

Weapon script

Damage, fire rate, pellets, penetration, clip size, aim zoom.

Compiled

One big table

Spread cones, view kick and camera recoil for every gun.

Compiled

Per-gun code

Movement speed, dry-fire timing, tracers.

Console only

38 console variables

A burst recoil path that is switched off for most guns.

Compiled

Scattered checks

Automatic or semi, slug damage, heat, slide lock.

The feel itself has little to tune. Every gun shares one accuracy model with no per-gun values. Recoil is a flat random draw with no pattern, no recovery and no smoothing. Crouching, walking and leaning barely matter. Nothing moves the camera or the gun model from code when a shot fires, beyond a small punch.

2 / Proposal summary

One record per gun, one place to tune it, and a proof that nothing moved

  1. One handling record per gun, built on archetypes. Every lever becomes a named value. A gun belongs to a family, such as rifle or shotgun, and states only what makes it different.
  2. One lever list in code. The file reader, the file writer, the console commands and the tuning panel are all generated from it. Adding a lever later is one row in the list and one field in the record, plus the code that uses it.
  3. One handling controller. The maths for spread, kick and recoil moves into a single testable unit that every gun goes through.
  4. Live tuning. On a private test server, a docked panel or a console command changes a lever while you play. A save button writes it back to the gun's file.
  5. New mechanisms, switched off by default. Recoil patterns with separately tuned randomness, recovery, stance modifiers, camera feedback and viewmodel handling arrive as more levers. No gun changes until someone tunes it.

The move is a pure reorganisation. A report of every gun's values is captured before the work and compared after every step. They must match.

3 / Breakdown

What tuning looks like afterwards

  1. Start a private server on the test map and press the panel key.
  2. The panel docks on the right and shows the gun in your hands. You keep moving and shooting.
  3. Hold a key to free the mouse, drag a slider, let go, fire. The change is live on the next shot.
  4. Flip the target from the gun to its family to move every rifle at once. A rifle that sets its own value for that lever keeps it.
  5. Press save. Only that gun's handling block in its file changes, or that family's block in the family file, so the edit is a small, reviewable diff.

The panel is built, and it sends every edit through the same console commands, so the panel and the console are one path. One difference from the sketch above: the panel's reload button reloads only the gun or the family the switch points at.

Archetypes: seven families already exist in the numbers

Today's values cluster on their own. Each family below lists what every member shares right now. A family holds the value most of its members use, and a gun that differs states its own. Where the numbers alone do not settle a gun's family, how the gun is fired and at what range decides it. The before-and-after report proves that no gun's values change.

This list is a starting point. It is neither complete nor final. Families can be added, renamed, split or merged as the guns are tuned, and a gun can move from one family to another.

Recoil today: three channels, all purely random

The game has three separate ways a shot disturbs your aim. Each gun uses a different mix, and every one draws a flat random number between a minimum and a maximum.

ChannelWhat you seeBuilds over a burstServer can check itGuns using it

Camera climbThe camera rises and stays until you pull it down.YesNo9
Shot rotationBullets leave above the crosshair. The camera does not move.YesYes3, by accident

Patterns will be built on the camera climb, as ruled. It is the channel a player fights with the mouse, which is what makes a pattern learnable.

Pattern and randomness, tuned separately

Each recoil channel computes a shot the same way. A fixed pattern and a random draw each get their own scale, so a gun can be fully learnable, fully random or any mix. Since 2026-11-15 the camera climb works this way in the game. The other two channels have the scaled random part and no pattern yet.

shot offset = pattern[shot number] x pattern influence
            + random(min, max)     x random scale

Pattern kick is a new idea, added on 2026-11-15. A fixed pattern climbs by the same step every time, which reads as smooth. Pattern kick keeps the pattern's path and makes each shot take a larger or smaller bite of it at random. Most shots move a little and some jump, while the average climb stays the same, so the gun feels kicky and the path can still be learned. It is a proposal: the game does not have this lever yet.

Pattern flip is a second new idea from the same day. Before each burst the gun decides whether to follow its pattern as drawn or the mirror image of it. At 0 it never flips, at 0.5 both are equally likely, and at 1 it always flips. A player can learn the shape and still has to read which way each burst is going. It is a proposal too: the game does not have this lever yet.

One gun can carry any pattern. A pattern is a list of points stored with the gun or its family. It is data, so it can be replaced while the game runs, and the levers do not change when it is.

The new mechanisms

All of these are added as levers on the same record, in the same panel, with defaults that reproduce today's game.

Camera feedback comes with one player setting that scales all of it down to zero, for people who are sensitive to camera motion.

The stance matrix

Six states by five outputs, every cell a multiplier that starts at 1. The marked cells are where today's game already treats a stance differently. Those rules are the same for every gun and cannot be tuned yet.

Is every stance treated the same today? Mostly, yes. Firing does not care about stance for most of these values. The exceptions are few. Crouching lets accuracy recover nearly twice as fast. Moving while firing from the hip, and being in the air, both make accuracy worse for as long as they last. Aiming switches a gun to its own tighter spread cones and its own recoil scale. Walking and leaning change nothing. Each marked cell in the table links to the lines of the game's public source that do it.

How a live change stays in step

The game runs the same shooting code twice, once on the server and once on your own machine so that firing feels instant. If the two disagree on a number, your screen stutters. So a change always goes to the server first, and the server tells every client.

This holds even for a value only your own machine uses, such as the camera effects that phase 4 adds, because the server's copy is the one a save writes to disk. A family change follows the same path: each side updates the family, then moves every member gun that does not set its own value, using the same rule. A reload reads the file again on the server and then on each client.

5 / Supporting detail

Decisions already made

QuestionRuling

Fix the defects found along the way?No. Preserve each one and file it upstream separately.

How does save write the file?It rewrites only the handling block, so comments in the file survive.

Two accepted consequences

Camera climb is trusted to the player's machine. The server cannot check it, so a modified game client can skip a patterned climb, as it can skip the Kyla's climb today.

Not for public servers yet. Until the server sends its values to joining players, a player could remove camera recoil with a text edit, and a server with custom tuning would feel uneven to players with stock files. That sync must land with, or before, the upstream change that moves camera recoil into files. Until then a live edit also lasts only until a reload, a save or the game closes, and a player who joins after an edit gets the values on disk.

What the investigation turned up

Thirteen defects and oddities were found. None is fixed by this work. The ones a designer would notice:

  • The scoped Jitte identifies itself as the plain Jitte, so anything that looks for the scoped one never finds it.
  • Two loadout entries both hand out the silenced M41. The scoped M41L cannot be picked from a loadout.
  • The display names for the M41L and M41S are swapped in one table.
  • AA13 and Supa 7 shells never penetrate walls. Only the slug does.
  • Reloading throws away the rounds left in the magazine. This reads as the original game's rule.
  • The MX and the Tachi show a different viewmodel field of view from the one written in their files, because the game reads a different key.

Not in this work

  • Any change to how a gun feels. Tuning starts after this lands.
  • Knife, grenades, detpack and ghost.
  • Bot behaviour tables.
  • Folding the AA13 and Supa 7 into the shared fire routine.
  • Live tuning on dedicated servers.

Still open

  • The feel check by hand, the PBK56S and a release build, as listed under the plan.

Live tuning, recorded in a running game

This clip comes from the game's own frame capture on a private test server. A script typed every command. The five parts were recorded one after another and joined, with a caption added to each. The panel on the right is the tuning panel, and its top rows show the live state of the gun.

  1. Stock MX. A short burst. The camera does not climb, because the MX has no camera recoil today.
  2. A pattern, set live. Twelve points of climb and drift are typed into the console while the game runs. The same burst now climbs and drifts along the pattern.
  3. Pattern scale 2. One lever doubles the whole pattern.
  4. Shot counter cool-down. With a recovery rate set, the Shot number at the top of the panel counts back down gradually after the burst. Before, it dropped to zero in one step.
  5. Reload. One command puts every value back to what is on disk, and the burst is stock again.

The wall is the test map's measuring wall. Each tile is 128 game units square, and each figure is 72 units tall, the height of a player. The bullet holes are cleared before every part, so the marks on the wall belong to that part's burst alone.
